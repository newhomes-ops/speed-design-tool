This browser can't run the tool

SPEED needs the File System Access API to create project folders and copy drawing files. Only Chromium-based browsers implement it.

Use Microsoft Edge or Google Chrome. Firefox and Safari do not support it, and there is no workaround.

If you are already in Edge or Chrome and see this message, the file may be opened from a location the browser treats as untrusted. Copy it to a local folder and open it again.

Conductor sizing convention — read this before stamping
Conductors are sized to max(1.25 × Ibranch, Ibranch ÷ tempFactor ÷ fillFactor), taken from IPlot-Tool. This reads NEC 690.8(B) as two independent requirements where the larger governs.

Permit Calc.xlsx computes it differently — (1.25 × I) ÷ tempFactor ÷ fillFactor — applying derating on top of the 125% uplift. That is more conservative and can call for a larger conductor. The two agree at low currents and diverge as derating becomes severe. Confirm which convention your EOR signs off on before this output goes onto a stamped drawing.

Reference data
Save to folder writes this table to <SPEED folder>/Reference Data/<TABLE>.json. That file is loaded on every start and overrides the copy built into SPEED.html — so edits survive without touching GitHub.

Because the JSON lives in your SPEED folder, two designers pointing at two different folders will drift apart. Keep one shared SPEED folder if the whole team must calculate from the same data. Each tab shows whether it is running built-in or folder data.
Why some tables must stay sorted
RT_AMPACITY, RT_EGC and RT_BREAKERS are searched with .find(), which returns the first row meeting the requirement. If a row is inserted out of order the lookup silently returns the wrong conductor or breaker — no error, just an incorrect drawing. Validate checks the ordering and blocks export if it is broken.

Duplicate keys are blocked for the same reason: the second row would be unreachable.
